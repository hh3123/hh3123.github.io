Reproducible Python images, line by line

2026-08-30

If the image hash changes when only your source changes, your layers are wrong.

A good Python image rebuilds dependencies only when dependencies change. Most Dockerfiles rebuild them on every commit because the manifest is copied after the source, or because the lockfile is not honoured.

Copy and install first

COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev
COPY . .
RUN uv sync --frozen --no-dev

The first install is cached as long as the manifest is unchanged; the second is a no-op that only re-checks the virtualenv.

Pin the base too

FROM python:3.12-slim moves under you. Pin a digest when you need bit-for-bit reproducibility, and bump it deliberately with a changelog entry.

Keep the runtime minimal

  • Multi-stage build: compile wheels in a builder, copy the venv into a slim runtime.
  • No build toolchain in the final layer.
  • Run as a non-root user with an explicit USER.
